# /deploy — выкладка сайта монастыря

Полный деплой проекта vladmon.ru. **Код** едет через git → GitHub Actions, **медиафайлы** (`public/photos/`, не в git) — напрямую rsync'ом на VPS.

## Контекст инфраструктуры

- Репозиторий: `origin` → https://github.com/nifontpro/vladmon, ветка `main`.
- CI: пуш в `main` → GitHub Actions собирает (`npm ci && npm run build`) и rsync'ит `dist/` на сервер (с `--exclude=/photos/`).
- VPS: `nifont@vladmon.ru`, SSH-ключ `~/.ssh/id_rsa`.
- Медиа на сервере: `/var/www/vladmon.ru/photos/` (nginx отдаёт как `/photos/...`).
- `public/photos/` исключён из git (`.gitignore`) — поэтому деплоится отдельно этой командой.

## Шаги (выполняй строго по порядку, останавливайся при ошибке)

### 1. Проверки сборки

Прогони и **дождись успеха**. Если что-то падает — НЕ коммить и НЕ деплой, покажи ошибку и остановись.

```bash
npm run build && npm run lint
```

### 2. Показать, что меняется

```bash
git status --short
git log origin/main..HEAD --oneline 2>/dev/null
```

Покажи пользователю сводку: какие файлы кода изменены, сколько новых медиа в `public/photos/`. Если менять нечего и медиа не изменились — скажи об этом и заверши.

### 3. Коммит и пуш кода в main

Убедись, что текущая ветка — `main` (`git branch --show-current`). Если нет — спроси пользователя, прежде чем продолжать.

Сформируй осмысленное сообщение коммита из реально сделанных изменений (на русском, без эмодзи — по правилам проекта). Закоммить весь код и запушь:

```bash
git add -A
git commit -m "<краткое описание изменений>

Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>"
git push origin main
```

Пуш запускает GitHub Actions — код задеплоится автоматически (1–2 мин).

### 4. Синхронизация медиа на VPS (rsync)

Залей медиафайлы напрямую. **Без `--delete`** — чтобы случайно не снести то, что есть на сервере (новые файлы добавятся, изменённые обновятся):

```bash
rsync -avz --stats \
  -e "ssh -i ~/.ssh/id_rsa -o StrictHostKeyChecking=no" \
  public/photos/ \
  nifont@vladmon.ru:/var/www/vladmon.ru/photos/
```

> Примечание: на macOS системный rsync старый (BSD 2.6.9) и не понимает `--info=progress2` —
> используем `--stats`. Если поставлен свежий rsync (через brew) — можно вернуть `--info=progress2`.

Покажи итог rsync (сколько файлов передано, объём).

> Если когда-то понадобится удалить с сервера медиа, которых уже нет локально, — добавь `--delete`, но **только с явного подтверждения пользователя** (операция необратима).

### 5. Итог

Сообщи пользователю:
- ✅ код запушен в `main`, ссылка на Actions: https://github.com/nifontpro/vladmon/actions (деплой кода идёт ~1–2 мин);
- ✅ медиа синхронизированы (N файлов, объём);
- сайт: https://vladmon.ru — попроси проверить через минуту-другую, когда CI завершит сборку.

## Важно

- Git-коммит делается ТОЛЬКО в рамках этой команды (пользователь её явно вызвал = разрешение на коммит).
- Не коммить `raw/` и `public/photos/` (исключены в `.gitignore`). `wiki/` исторически отслеживается — его изменения коммить вместе с кодом.
- При любой ошибке на шагах 1–3 останавливайся и показывай вывод. Шаг 4 (rsync) можно повторять независимо.
