# CLAUDE.md — корневая инструкция проекта

Этот файл — инструкция для LLM-агента (Claude Code) при работе с этим репозиторием. Прочитай его в начале каждой сессии и следуй ему.

В одной директории живут **два независимых контекста**:

1. **React-сайт монастыря** — основной проект (`src/`, `public/`, `package.json`, `index.html`, и т.д.). Эстетика дизайн-системы «Цѣркъ».
2. **LLM Wiki** — персональная исследовательская база знаний по методу Карпатии (`wiki/`, `raw/`). Никак не пересекается с React-сборкой.

Обе части управляются по разным правилам — см. ниже.

---

## ПРИ СТАРТЕ КАЖДОЙ СЕССИИ — ОБЯЗАТЕЛЬНО

Прежде чем отвечать пользователю или брать задачу, прочитай эти файлы (в указанном порядке):

1. **`wiki/index.md`** — каталог всех страниц LLM Wiki. Минута чтения, даёт карту того, какие знания уже накоплены.
2. **`wiki/overview.md`** — тема исследования и текущий тезис. Обязательно, чтобы понимать, о каком монастыре речь.
3. **Хвост `wiki/log.md`** — последние 5–10 записей. Можно через `grep "^## \[" wiki/log.md | tail -10`. Это покажет, что недавно делалось.
4. **Если есть `wiki/synthesis/project-snapshot-*.md`** — прочитать самый свежий (по дате в имени). Там полный контекст разработки сайта.

**Зачем:** этот проект включает LLM Wiki, которая накапливает знания между сессиями. Без чтения этих 4 файлов ты будешь работать «вслепую» и переспрашивать пользователя о том, что уже зафиксировано. Пользователь явно не хочет повторять контекст — ты сам его подтягиваешь.

**Когда не нужно читать:** только если задача целиком про конфиги сборки (`vite.config.ts`, `tsconfig`) или одна простая правка вне `wiki/`/`raw/`/`src/shared/config/`.

## ЧАСТЬ I. React-сайт монастыря

### I.1. Стек

- Сборка: Vite 8 + TypeScript 6
- UI: React 19.2 + Tailwind CSS v4 (`@tailwindcss/vite`)
- Роутинг: React Router 7 (lazy-роуты)
- Состояние: Zustand 5 (auth, theme) + TanStack Query 5 (server)
- Формы: react-hook-form + Zod 4
- Анимации: Motion 12
- Иконки: собственный SVG-спрайт (`src/shared/icons/sprite.tsx`) + lucide-react
- Линт: ESLint 10 (flat config) + Prettier 3

### I.2. Структура (lite-FSD)

```
src/
├── app/         # провайдеры (QueryClient), router, layout
├── pages/       # 6 страниц (home, history, today, schedule, notes, contacts) + 404
├── widgets/     # композиционные блоки (header, footer, ornament-band, today-card, …)
├── features/    # auth (каркас), notes-form
├── entities/    # модели данных (user, note, service)
└── shared/      # ui-обёртки, иконки, lib (cn, jwt, api), стили, конфиг
public/
├── fonts/       # 5 OTF (Monomakh, Fedorovsk, Vertograd, Ponomar, Indiction)
├── ornaments/   # декоративные сканы
└── favicon.svg  # 8-конечный крест
```

### I.3. Команды

```bash
npm install          # установка
npm run dev          # dev-сервер на :5173
npm run build        # tsc -b && vite build
npm run lint         # ESLint
npm run preview      # просмотр прод-сборки
```

### I.4. Конвенции

- **Алиас `@/*` → `src/*`** (настроено в `vite.config.ts` и `tsconfig.app.json`).
- **kebab-case** для имён файлов.
- **Цвета и токены** — только через CSS-переменные `--cerk-*` (определены в `src/shared/styles/tokens.css`). Для Tailwind utility-классов — `bg-paper-01`, `text-rubric`, `font-display` и т.п. (мостик в `src/shared/styles/index.css` через `@theme`).
- **Шрифты:**
  - `font-display` (заголовки и буквицы) — Monomakh / Fedorovsk
  - `font-body` (длинный текст) — Literata
  - `font-ui` (интерфейс) — Onest
  - **Тексты пишутся современным русским языком** — никаких ѣ/і/ѳ/ѵ/конечных ъ.
- **Никаких mock-токенов в localStorage.** Auth-каркас готов, но кнопки `submit` отключены до Kotlin-бэкенда.
- **Все плейсхолдеры** в `src/shared/config/meta.ts` помечены `[ТЕКСТ-ЗАГЛУШКА]` или `ФОТО ТРЕБУЕТСЯ`.

### I.5. Что НЕ делать

- Не делать `git commit` самостоятельно — правило пользователя.
- Не использовать эмодзи в коде и интерфейсе, если пользователь явно не попросил.
- Не добавлять зависимости без согласования.
- Не лезть в `wiki/` и `raw/` при работе над React-частью.

## ЧАСТЬ II. LLM Wiki (метод Карпатии)

`wiki/` и `raw/` — это персональная исследовательская база знаний, построенная по паттерну Andrej Karpathy's LLM Wiki. **Это не часть React-проекта** и не должно попадать ни в Vite-сборку, ни в TypeScript-чек, ни в ESLint, ни в production bundle. Защита настроена:

- `eslint.config.js` → `globalIgnores(['wiki', 'raw', 'dist', 'node_modules'])`
- `.prettierignore` → `wiki/`, `raw/`
- Vite по умолчанию не читает за пределами `src/` и `public/`
- `tsconfig.app.json` → `"include": ["src"]`

**Тема исследования:** _(будет уточнена пользователем по ходу работы — обнови этот раздел, когда тема прояснится)_

### II.1. Архитектура — три слоя LLM Wiki

```
app/
├── raw/                  ← СЛОЙ 1: сырые источники (immutable)
│   ├── README.md
│   ├── assets/           ← изображения (Obsidian attachment folder)
│   └── *.md, *.pdf, ...  ← статьи, заметки, выгрузки
└── wiki/                 ← СЛОЙ 2: сгенерированные страницы (mutable, моё)
    ├── index.md          ← каталог всех страниц
    ├── log.md            ← хронологический журнал операций
    ├── overview.md       ← верхнеуровневый обзор + текущий тезис
    ├── sources/          ← резюме каждого источника
    ├── entities/         ← сущности (люди, организации, продукты, места)
    ├── concepts/         ← концепции, идеи, методы, теории
    └── synthesis/        ← сводные страницы, сравнения, выводы
```

**Правила слоёв:**
- `raw/` — **никогда не редактирую** содержимое (только читаю). Источник истины.
- `wiki/` — **владею полностью**. Создаю, обновляю, переименовываю, удаляю страницы.
- Этот `CLAUDE.md` — со-эволюционирует с пользователем.

### II.2. Конвенции для страниц `wiki/`

#### Имена файлов
- `kebab-case.md`. Пример: `transformer-architecture.md`, `andrej-karpathy.md`.
- Для русскоязычных терминов — транслит или латинский аналог.
- Один файл = одна сущность/концепция/источник.

#### YAML frontmatter (Obsidian-совместимый)

```yaml
---
type: source | entity | concept | synthesis | overview
title: Человекочитаемое название
aliases: [синонимы]
tags: [тег1, тег2]
created: 2026-05-14
updated: 2026-05-14
source_count: 3
sources: [[source-slug-1]], [[source-slug-2]]
---
```

Для `source` дополнительно: `source_url`, `source_author`, `source_date`, `source_type`.

#### Wiki-links
- `[[slug-страницы]]` или `[[slug-страницы|подпись]]`.
- На источники — `[[sources/source-slug]]` (или короткий `[[source-slug]]`).
- Линкуй щедро. Несуществующий `[[link]]` — маркер «здесь нужна страница».

#### Структура страницы
- **Source**: TL;DR → ключевые тезисы → цитаты → раздел «связи с вики».
- **Entity**: определение → роль → ключевые факты → источники → связи.
- **Concept**: определение → как трактуется (с расхождениями) → пример → связи.
- **Synthesis**: свободная форма, всегда с цитатами на источники.

#### Цитирование
Любой факт в `wiki/` должен ссылаться на источник: `… согласно [[sources/karpathy-llm-wiki]]`. Без источника — не пишу. Если моя гипотеза — явно помечаю: «**Гипотеза (моя):** …», «**Открытый вопрос:** …».

### II.3. Операции

#### Ingest (приём новых источников) — БАТЧЕВЫЙ

Пользователь предпочитает батчевую обработку с минимумом диалога.

1. Пользователь кладёт файлы в `raw/` и говорит «обработай новые источники».
2. Нахожу все необработанные файлы в `raw/` (которых нет в `wiki/sources/` и в `log.md`).
3. Для каждого источника:
   - Читаю полностью.
   - Создаю `wiki/sources/<slug>.md` по шаблону.
   - Извлекаю упомянутые сущности и концепции. Если страница есть — обновляю. Если нет — создаю.
   - Обновляю `wiki/index.md`. Дописываю запись в `wiki/log.md`.
4. После батча: обновляю `wiki/overview.md` (если новые данные меняют тезис). Выдаю короткое резюме.
5. По каждому источнику отдельно не уточняю детали — отмечаю в резюме батча, что было неожиданного.

#### Query (вопросы по вики)

1. Сначала `wiki/index.md` — нахожу релевантные страницы.
2. Читаю их. При необходимости — `raw/` источники для точных цитат.
3. Отвечаю с цитатами `[[…]]`.
4. Если ответ ценный (сравнение, новый ракурс) — предлагаю сохранить как `wiki/synthesis/`. Молча не сохраняю.

#### Lint (проверка здоровья вики)

По запросу «прогони lint»:
- Противоречия между страницами.
- Устаревшие утверждения.
- Орфаны (страницы без входящих ссылок).
- Несозданные `[[ссылки]]` — кандидаты в новые страницы.
- Пробелы: концепции упоминаются, но без отдельной страницы.
- Несоответствия frontmatter.

Действия — только после подтверждения пользователя.

### II.4. Спецфайлы

#### `wiki/index.md` — каталог
Группировка: `## Overview`, `## Sources`, `## Entities`, `## Concepts`, `## Synthesis`. Каждая строка: `- [[slug]] — описание`.

#### `wiki/log.md` — журнал (append-only)
Формат: `## [YYYY-MM-DD] <op> | <subject>` — парсится `grep "^## \[" log.md | tail -N`.

#### `wiki/overview.md`
Тема исследования, текущий тезис (1–2 абзаца), ключевые открытые вопросы, ссылки на хабовые страницы.

### II.5. Чего НЕ делать с LLM Wiki

- Не редактировать `raw/`.
- Не записывать факты без ссылки на источник.
- Не создавать страницы «впрок».
- Не дублировать содержимое.
- Не «придумывать» — если не знаю, говорю, что не знаю.

## ЧАСТЬ III. Граница между React-сайтом и LLM Wiki

| Аспект | React-сайт | LLM Wiki |
|---|---|---|
| Где | `src/`, `public/`, `index.html`, конфиги | `wiki/`, `raw/` |
| Что туда попадает | Код приложения | Markdown-источники и страницы |
| Сборка / линт / TS | Да | Нет (явно исключены) |
| Кто пишет | Я (через Edit/Write) | Я (через Edit/Write) |
| Кто читает на проде | Браузер пользователя | Никто (только редактор/Obsidian) |

**Если работаю над сайтом** — никаких вторжений в `wiki/`/`raw/`.
**Если работаю над вики** — никаких вторжений в `src/`/`public/`.
