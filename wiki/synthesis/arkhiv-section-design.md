# Раздел сайта «Архив» — проектировка

## Запрос пользователя

> «Позже я буду добавлять новые современные фотографии. И, кстати, нужно будет подумать, сделать отдельный раздел с архивом, где будут фотографии прям архивных данных и их текстовые расшифровки.»

То есть: отдельная страница сайта, посвящённая историческим документам обители. Каждая единица — фотография архивного документа + текстовая расшифровка.

## Что доступно уже сейчас

Из обработанных источников можно собрать первое наполнение архива:

- «Послужный список о монашествующих и послушниках Вьясского Владимирского мужского монастыря за 1914 год».
- «Ведомость о капиталах, принадлежащих Вьясскому Владимиррскому монастырю».

Все три документа имеют расшифровку в источнике, но фотографий оригиналов в `raw/` пока нет — это материал из ЦГА РМ и ГАПО.

## Концепция раздела сайта

### Имя и URL

- Маршрут: `/archive` (или `/архив`).
- В навигации: в конце основного меню, после «Контакты» (чтобы не дробить главные пять-шесть пунктов).
- Эстетика — соответствует «Цѣркъ»: paper-00 фон, рубричные буквицы, монохромная палитра, серифные шрифты тела (Literata).

### Структура страницы

Главная страница `/archive` — каталог-указатель, организованный по разделам:

1. **Документы обители** (Ведомости 1914 года, материалы Архива УФСБ).
2. **Свидетельства и воспоминания** (мемуары насельников и паломников).
3. **Газетные публикации** (интервью, новости о возрождении).
4. **Фотохроника** (исторические фото с подписями).
5. **Чудеса и исцеления** (отдельный подраздел — по [[vladimirskaya-vyasskaya-icon]]).

### Карточка единицы архива

Каждая единица — отдельная страница `/archive/<slug>` со схемой:

```
┌────────────────────────────────────────┐
│ Заголовок (например: «Ведомость 1914») │
│ Дата · Тип документа · Источник        │
├────────────────────────────────────────┤
│ [Фото оригинала / скан]                │
│  (если есть; справа — миниатюра)       │
├────────────────────────────────────────┤
│  Текстовая расшифровка                 │
│  с моноширинными вставками,            │
│  если документ — таблица.              │
├────────────────────────────────────────┤
│  Комментарий редактора (опционально):  │
│  контекст, перекрёстные ссылки.        │
└────────────────────────────────────────┘
```

### Модель данных

В `src/shared/config/meta.ts` (или отдельный `archive.ts`):

```ts
type ArchiveEntry = {
  slug: string;          // 'vedomost-1914'
  category: 'documents' | 'memoirs' | 'press' | 'photos' | 'miracles';
  title: string;
  date?: string;         // ISO или вольный текст ('27 августа 1923')
  source: string;        // 'ЦГА РМ', 'Архив УФСБ', 'газета "Знамя труда"'
  authors?: string[];    // ['архимандрит Геронтий (Титов)']
  photoSrc?: string;     // '/photos/archive/...'
  body: string;          // markdown-расшифровка
  notes?: string;        // комментарий редактора
  relatedWikiPages?: string[]; // ['bolshevyassky-monastery', ...]
};
```

### Технические тонкости

- Markdown в `body` потребует рендерера. Минимальный путь — установить `react-markdown` + `remark-gfm` (нужно согласовать с пользователем, по правилам CLAUDE.md не добавлять зависимости без подтверждения).
- Альтернатива без зависимости — хранить расшифровки как `ReactNode` (JSX) в самом конфиге. Хуже для длинных текстов.
- Фото оригиналов документов класть в `public/photos/archive/`.

## План на следующие сессии

1. **Уточнить у пользователя** структуру и приоритеты:
   - Какие документы хочется опубликовать первыми (Ведомость 1914? стихи Викентия? записки ГПУ?).
   - Готовность ставить `react-markdown` ради удобного рендеринга длинных расшифровок.
2. После согласования — спроектировать TypeScript-модель и страницу `/archive`.
3. Реализовать каталог и одну-две заполненные карточки на материале, который уже есть в источниках.
4. Дальше — итеративно: пользователь добавляет новые фото архивных документов в `raw/`, я ингещу и формирую карточки.
